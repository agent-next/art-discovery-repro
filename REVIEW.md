# REVIEW.md — repo-specific review rules

Scope: agent-next/art-discovery-repro (reproduction of Yoon et al. 2026, the Anthropic
ART paper). Every finder/verifier prompt must consult this file.

## Always-check (confirmed bug classes from the 5-round grok review, 2026-09-24)

1. **Cite-then-recount constants against `docs/paper-notes.md`.** A page number
   ("29") was once misread as a data value (novel clades = 16). Any numeric
   constant in `pipeline/` or `benchmark/` must match the ledger, and the quota
   arithmetic must close exactly (e.g. anchors sum == 7,308).
2. **External-tool flags must be real.** `--cov-mode` was invented for
   `diamond cluster` (real flags: `--member-cover`/`--mutual-cover`, PERCENT
   units). Verify flag names + units against the tool's docs, not plausibility.
3. **Dead wiring.** A declared rule (short-spacing suppression) existed as an
   unused helper while the header claimed it ran. If code documents a behavior,
   a test or grep-able call site must prove it is wired.
4. **Tests that lock wrong behavior.** The OR-vs-AND weak-hit rule was "covered"
   by a test asserting the wrong semantics. When fixing a finding, rewrite the
   test to assert the corrected paper semantics, not just to pass.
5. **Function-local imports used across branches.** `import re` inside one
   branch made `re` a function-local name and raised UnboundLocalError on
   another path. Imports go at module top.
6. **Fail-safe verdict parsing.** LLM-returned verdicts (supervisor VERDICT:,
   editor FILE:) parse to None on absence; consumers must fail TOWARD the safe
   action (revise / not-file), never treat None as success.
7. **Window direction.** Upstream strings END at the RT; subwindows must take
   the TAIL (`[-3000:]`), not the prefix, when clamping to paper limits.
8. **Offset threading.** `DelimitedArray.block_offset` must survive every
   constructor round-trip (`pwm_extend` once reset it to 0) and PWM consumers
   must slice `copy_start + block_offset`.
9. **Provenance labels.** Values not stated by the paper carry
   `NOT-IN-PAPER:`/`PLACEHOLDER-CLASS-SPECIFIC:`/`GAP:` — findings should flag
   any magic number without one.
10. **StrEnum ordering traps.** `TaskStatus` members are strings: `<` compares
   them ALPHABETICALLY, not by lifecycle. Never order-compare enum members for
   state gates (`file_report` once accepted ACCEPTED and refused EXECUTED this
   way). Compare against explicit states, or keep an explicit order list.
11. **Aggregate fields over overlapping structures.** When a counter sums two
   collections (e.g. `store` + `queue`), check they are disjoint — the task
   queue is a subset of the store and `tasks_total` silently doubled.

## Fixture-trap class (S3 gate, 2026-09-25)

A test fixture must not fight the code under test's convenience paths:
`EmptyRevision` deleted `summary.md` BEFORE calling the scripted writer, which
only writes when the file is missing — it resurrected the file and the
"completion check" under test never fired (the test passed via an unrelated
stall mode). Rule: a power test asserts the COUNTERS/mode that identify the
path under test (e.g. `gate_failures` vs `revisions`), not just the terminal
status both paths share.

## Skip lists

- `__pycache__/`, `.venv/`, `uv.lock` (generated) — not reviewed.
- `task-runs/` receipts — historical records; review only for secrets.
- `docs/paper-notes.md` content fidelity to the paper itself was checked line
  by line against the PDF on 2026-09-24; re-check only where code disagrees.

## Bars

- Findings: `file:line` + concrete failure scenario + confidence 0-1 + severity
  (critical | major | minor | pre-existing). Citations must be exact or the
  finding is rejected.
- Fixes: every fixed bug gets a regression-power test (disabled-vs-enabled must
  differ). Fixtures are generated by code, never hand-crafted bytes.
- Negative claims ("no bug of class X exists") need a demonstrated positive:
  show the check firing on a known-bad input.
